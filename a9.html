O problema do tamanho fixo

Para guardar alunos, a primeira ideia é um vetor: struct Aluno turma[1000];. Funciona, mas o número 1000 foi escolhido antes de o programa rodar.

  • Se aparecerem 1200 alunos, não cabe. Aumentar para 5.000, depois 20.000, só adia o problema.
  • Se a turma tiver 30 alunos, os outros 970 espaços ficam reservados à toa: desperdício de memória.

Isso é alocação estática: o compilador reserva o espaço na declaração, ele existe mesmo que nunca seja usado, e o tamanho não muda durante a execução.

Alocação dinâmicaO espaço é pedido em tempo de execução, do tamanho que o programa descobriu que precisa. Serve para dados de tamanho variável, para estruturas como listas e árvores e para não desperdiçar memória.

malloc e sizeof

malloc (da biblioteca stdlib.h) reserva um bloco de bytes na heap e devolve o endereço do primeiro byte. Esse endereço vai para um ponteiro.

#include <stdio.h>
#include <stdlib.h>

int main() {
    int *p;
    p = (int *) malloc(100 * sizeof(int));   /* 100 inteiros: 400 bytes se int tem 4 */
    if (p == NULL) {
        printf("Sem memoria\n");
        return 1;
    }
    /* ... usar p ... */
    free(p);
    return 0;
}
  • sizeof(int) dá o tamanho de um int em bytes. Multiplicar pela quantidade dá o total: 5 * sizeof(int) reserva espaço para 5 inteiros.
  • (int *) converte o endereço devolvido (um void *) para ponteiro de int.
  • Se não houver um bloco livre do tamanho pedido, malloc devolve NULL. Sempre teste antes de usar, para não ter segmentation fault.
  • Para texto: char *s = (char *) malloc((n + 1) * sizeof(char)); — o + 1 é o espaço do '\0'.
Erros comunsmalloc(sizeof int) não compila: com um tipo, os parênteses de sizeof são obrigatórios. malloc(n) reserva n bytes, não n inteiros. E esquecer #include <stdlib.h> deixa malloc sem declaração.

Um vetor do tamanho certo

malloc reserva um bloco contíguo. Como os elementos ficam lado a lado, a aritmética de ponteiros da A8 funciona e o ponteiro pode ser usado com colchetes, como um vetor. A diferença é que o tamanho é decidido durante a execução.

int n;
printf("Quantos numeros? ");
scanf("%d", &n);

int *v = (int *) malloc(n * sizeof(int));
if (v == NULL) return 1;

for (int i = 0; i < n; i++)
    scanf("%d", &v[i]);          /* v[i] é o mesmo que *(v + i) */

for (int i = 0; i < n; i++)
    printf("%d ", v[i]);

free(v);

O resto é igual a um vetor comum: laços de 0 a n - 1, somas, médias, maior e menor.

free e vazamento de memória

Memória pedida com malloc fica ocupada até alguém devolver. Quem devolve é free(ponteiro).

Esquecer o free causa um memory leak: o programa não usa mais aquele bloco, mas o sistema continua vendo-o como ocupado. Pense num empréstimo: você pede um pedaço de memória, usa e esquece de devolver.

  • Passe para free o mesmo ponteiro que veio do malloc: free(p), não free(*p) nem free(&p).
  • Libere uma vez só, e depois não use mais o bloco.
  • Dois vetores alocados pedem dois free.

realloc: mudar o tamanho

A turma tinha 5 alunos e chegaram mais 3. O bloco de 5 notas precisa virar um bloco de 8 sem perder as 5 que já estão lá. Para isso existe realloc:

float *notas = (float *) malloc(5 * sizeof(float));
/* ... cinco notas lidas ... */
float *temp = (float *) realloc(notas, 8 * sizeof(float));
if (temp == NULL) {
    /* falhou: notas continua válido, com o conteúdo intacto */
    free(notas);
    return 1;
}
notas = temp;     /* agora cabem 8; as 5 primeiras foram preservadas */
  • Aumentar: se houver espaço logo depois do bloco, ele cresce no lugar. Senão, realloc aloca outro bloco, copia o conteúdo, libera o antigo e devolve o endereço novo.
  • Diminuir: o bloco encolhe; o conteúdo até o novo tamanho é mantido.
  • Falha: devolve NULL e não libera o bloco original. Por isso o resultado vai para um ponteiro temporário: notas = realloc(notas, ...) perderia o único endereço do bloco se desse NULL.
